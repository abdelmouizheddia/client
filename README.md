# AZZOUZ GYM الرياضية

نظام متكامل لإدارة نادي رياضي محلي (يعمل على localhost فقط، بدون أي اعتماد على الإنترنت أو خدمات سحابية)، مصمم لإدارة أكثر من 300 عضو مسجل عبر أربع رياضات: **السباحة، كمال الأجسام، كرة القدم، والكاراتيه**.

يتكون النظام من واجهة أمامية (React + TypeScript) وخادم خلفي (Node.js + Express + Prisma + SQLite)، بتصميم "Premium SaaS Dashboard" بألوان الأبيض والكحلي الغامق والذهبي (#D4AF37)، مع دعم كامل للغة العربية واتجاه RTL، والوضعين الفاتح والداكن.

---

## 1. لمحة عن البنية التقنية

| الطبقة | التقنية |
|---|---|
| الواجهة الأمامية | React 18 + TypeScript + Vite + TailwindCSS |
| الخادم الخلفي | Node.js + Express |
| قاعدة البيانات | SQLite (عبر Prisma ORM) |
| المصادقة | JWT (كلمة مرور واحدة للمسؤول، صلاحية الجلسة 12 ساعة) |
| الرسوم البيانية | Recharts |
| توليد PDF | html2canvas + jsPDF (من جهة المتصفح لضمان عرض صحيح للنص العربي) |
| رموز QR | مكتبة qrcode (للتوليد) و html5-qrcode (للمسح بالكاميرا) |
| استيراد/تصدير Excel | ExcelJS |

## 3. التثبيت والتشغيل (على جهازك الشخصي)

### المتطلبات
- Node.js إصدار 18 أو أحدث (تم تطوير المشروع باستخدام Node 22)
- npm (يأتي مرفقاً مع Node.js)

### الخطوة 1: تثبيت اعتماديات الخادم الخلفي

```bash
cd server
npm install
```

### الخطوة 2: توليد عميل Prisma وإنشاء قاعدة البيانات

```bash
npx prisma generate
npx prisma migrate dev --name init
```

هذا الأمر سينشئ ملف قاعدة بيانات SQLite جديد (`server/prisma/dev.db`) وفق المخطط المعرّف في `schema.prisma`.

### الخطوة 3: تعبئة بيانات تجريبية (اختياري لكن موصى به)

```bash
npm run seed
```

سيُنشئ هذا السكريبت: 4 رياضات، 8 مدربين، 55 عضواً ببيانات عربية واقعية (أعمار وحالات متنوعة)، اشتراكات وسجلات حضور وحركات مالية وإنجازات تجريبية، لتتمكن من استكشاف النظام فوراً بدون إدخال يدوي.

### الخطوة 4: تشغيل الخادم الخلفي

```bash
npm run dev
```

سيعمل الخادم على `http://localhost:5000`. عند أول تشغيل (إن لم تُشغّل سكريبت seed)، سيُنشئ النظام تلقائياً كلمة مرور افتراضية:

> **كلمة المرور الابتدائية: `admin1234`**
> يُرجى تغييرها فوراً من صفحة "الإعدادات" بعد أول تسجيل دخول.

### الخطوة 5: تثبيت وتشغيل الواجهة الأمامية

في نافذة طرفية جديدة:

```bash
cd client
npm install
npm run dev
```

ستعمل الواجهة على `http://localhost:5173` وتتصل تلقائياً بالخادم الخلفي عبر إعادة توجيه (proxy) معرّفة في `vite.config.ts`. افتح هذا الرابط في المتصفح لاستخدام النظام.

## 4. ⚠️ ملاحظة هامة بخصوص بيئة التطوير التي أُنشئ بها هذا المشروع

تم بناء هذا المشروع داخل بيئة تنفيذ معزولة (sandboxed) لا تسمح بالوصول إلى الشبكة لتنزيل محرك Prisma الثنائي (query engine binaries)، وبالتالي **لم يكن من الممكن تشغيل قاعدة البيانات أو اختبار الخادم الخلفي تشغيلاً فعلياً (runtime) داخل تلك البيئة**. تم تعويض ذلك بالخطوات التالية لضمان جودة الكود قبل التسليم:

- تم فحص جميع ملفات JavaScript للخادم الخلفي بأمر `node --check` للتأكد من سلامة الصياغة (syntax) في كل ملف، وقد نجحت جميعها بدون أي خطأ.
- تم تثبيت جميع اعتماديات الواجهة الأمامية فعلياً (`npm install`) وتنفيذ بناء كامل (`npm run build`) يتضمن فحص أنواع TypeScript الصارم (`tsc -b`) ثم تجميع Vite، وقد نجحت العملية بالكامل بدون أي خطأ.
- مخطط قاعدة البيانات (`schema.prisma`) ونقاط API ونماذج البيانات في الواجهة الأمامية تمت مطابقتها يدوياً حقلاً بحقل، واستجابة بنية بنية، للتأكد من توافق الواجهتين الأمامية والخلفية بدقة.

**بالتالي يوصى بشدة عند أول تشغيل على جهازك** أن تتبع خطوات التثبيت أعلاه بعناية وتختبر كل وحدة (الأعضاء، الاشتراكات، الحضور، المالية...) عملياً، وإن صادفت أي خطأ تشغيلي غير متوقع (وهو مستبعد لكن ممكن نظراً لعدم الاختبار الحي)، فالكود منظم بشكل يسهل تتبعه وتصحيحه بسرعة.

## 5. كلمة المرور وتسجيل الدخول

النظام يستخدم **كلمة مرور واحدة للمسؤول فقط** (بدون أسماء مستخدمين متعددة)، مخزّنة بشكل مُجزّأ (bcrypt) في جدول `Settings`. يمكن تغييرها من صفحة الإعدادات ← "تغيير كلمة المرور". الجلسة صالحة لمدة 12 ساعة عبر رمز JWT.

## 6. وحدات النظام (نظرة سريعة)

- **لوحة التحكم**: إحصائيات فورية (أعضاء نشطون، اشتراكات منتهية، دخل الشهر...) و5 رسوم بيانية (المداخيل الشهرية، توزيع الرياضات، التسجيلات الأسبوعية، الفئات العمرية، أعداد الرياضيين لكل رياضة) وقائمة أعياد ميلاد الشهر.
- **الأعضاء**: بحث وتصفية متقدمة، إضافة/تعديل مع صورة شخصية، أرشفة، استيراد/تصدير Excel، وصفحة ملف شخصي كاملة بعلامات تبويب (نظرة عامة، الاشتراكات، الحضور، الإنجازات، المستندات).
- **البطاقات الرقمية**: بطاقة عضوية رقمية مصممة بأسلوب راقٍ (ذهبي وكحلي) تحتوي رمز QR، قابلة للتصدير كـ PDF أو صورة أو الطباعة المباشرة.
- **الحضور**: تسجيل يدوي بالبحث عن العضو، أو مسح رمز QR عبر كاميرا الجهاز، مع ملخصات يومية/أسبوعية/شهرية.
- **الاشتراكات**: 4 باقات (شهر/3 أشهر/6 أشهر/سنة)، تنبيهات الاشتراكات المنتهية قريباً (تُحسب تلقائياً عند 7/3/0 أيام)، وتجديد بضغطة واحدة.
- **المالية**: تتبع المداخيل والمصاريف بفئات متعددة، تقارير بحسب الفترة (يومي/أسبوعي/شهري/سنوي/مخصص)، ورسوم بيانية لتطور الأرباح.
- **المدربون**: ملفات المدربين (الصورة، التخصص، الراتب، الجدول) وقائمة الأعضاء المسندين لكل مدرب.
- **الإنجازات**: تسجيل الميداليات والبطولات والشهادات لكل عضو.
- **التقارير**: توليد 5 أنواع تقارير (أعضاء، اشتراكات، حضور، مالية، مدربون) بصيغة PDF مهيأة للطباعة.
- **الأرشيف**: الأعضاء المؤرشفون (يدوياً أو تلقائياً) قابلون للاسترجاع الكامل أو الحذف النهائي.
- **الإعدادات**: معلومات النادي والشعار، كلمة المرور، الوضع الداكن/الفاتح، والنسخ الاحتياطي اليدوي والتلقائي.

## 7. قرارات تصميمية تستحق الذكر

### الأرشفة التلقائية (فترة سماح 30 يوماً)
لا يتم حذف أي عضو فوراً عند انتهاء اشتراكه. بل يُمنح 30 يوماً كفترة سماح (يمكن خلالها تجديد الاشتراك بسهولة)، وبعدها فقط تنقله المهمة المجدولة (cron، تعمل يومياً 03:00 صباحاً) تلقائياً إلى الأرشيف. يمكن أيضاً تشغيل هذه العملية يدوياً من صفحة الأرشيف. الأرشفة تحفظ نسخة كاملة (JSON) من بيانات العضو، فهي قابلة للاسترجاع الكامل في أي وقت.

### توليد PDF من جهة المتصفح
اخترنا تصيير عناصر HTML/CSS فعلية إلى صورة (html2canvas) ثم تضمينها في PDF (jsPDF) من جهة العميل، بدلاً من توليد PDF في الخادم. هذا يضمن عرضاً صحيحاً ومضبوطاً للنص العربي (الاتجاه والتشكيل)، وهي مشكلة معروفة في مكتبات PDF الخاصة بالخادم (مثل pdfkit) عند التعامل مع العربية.

### رمز العضوية (Member Code)
يُولَّد تلقائياً بصيغة `BTS-00001` بعد إنشاء العضو في قاعدة البيانات (يعتمد على الرقم التسلسلي الحقيقي لتجنب التعارض).
:
```
client/src/utils/format.ts → ثابت CURRENCY_LABEL
```

## 8. النسخ الاحتياطي

- **تلقائي**: نسخة احتياطية كاملة لقاعدة البيانات (`dev.db`) تُنشأ يومياً في الساعة 03:00 صباحاً، مع الاحتفاظ بآخر 30 نسخة فقط (الأقدم تُحذف تلقائياً).
- **يدوي**: من صفحة الإعدادات ← "النسخ الاحتياطي" ← "إنشاء نسخة احتياطية"، مع إمكانية الاستعادة أو الحذف لكل نسخة.
- عند استعادة نسخة احتياطية، يُنشأ تلقائياً نسخة أمان من القاعدة الحالية قبل الاستبدال، ويُنصح بإعادة تشغيل الخادم الخلفي بعد أي عملية استعادة.

## 9. ملاحظات إضافية

- جميع الصور والمستندات المرفوعة تُخزَّن محلياً في `server/uploads/` (بدون أي رفع لخدمات خارجية).
- المشروع مصمم للعمل بالكامل على الشبكة المحلية (localhost) فقط، بدون أي اعتماد على الإنترنت في وقت التشغيل (باستثناء تحميل الخطوط من Google Fonts عند أول فتح للصفحة - يمكن تحميلها محلياً إن رغبت بعزل كامل عن الإنترنت).
- تم اختبار حِزمة الواجهة الأمامية (`npm run build`) بنجاح؛ ملاحظة بسيطة: حجم الحزمة النهائية حوالي 1.3 ميغابايت بسبب مكتبات html2canvas/jsPDF/recharts/html5-qrcode، وهو أمر طبيعي ومقبول لتطبيق محلي ولا يؤثر على الأداء عملياً.
